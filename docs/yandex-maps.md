# Яндекс Карты в coffeely: что мы используем и что обязаны

Мы используем **Tiles API** по бесплатному тарифу: Leaflet на лендинге (`/map` и
пикер координат в кабинете) и та же страница `/map` внутри WebView приложения.
JavaScript API, MapKit, Геокодер, Static API и Панорамы **не используем**.

Официальные документы (проверено 2026-11-22):

- Условия использования отдельных сервисов «Яндекс Карт» — https://yandex.ru/legal/maps_api
  (публикация 01.09.2026);
- Оферта на коммерческие тарифы — https://yandex.ru/legal/maps_api_offer
  (размещена и вступила в силу 28.10.2026).

Markdown-версии: `https://yandex.ru/legal/maps_api/ru/index.md` и
`https://yandex.ru/legal/maps_api_offer/ru/index.md`.

## Своя геолокация: кнопка «Найти меня»

На странице `/map` (и в приложении) есть кнопка «Найти меня»: по нажатию
`navigator.geolocation.getCurrentPosition` отдаёт координаты, карта рисует точку
и круг точности и подводит к нему вид. Это наша собственная функция, а не
автоматический сбор Яндекса (п. 8.1 ниже).

- Координаты **не уходят на backend**: остаются в JavaScript внутри браузера или
  WebView, ни в API, ни в логи не пишутся.
- Исключение — кабинет владельца: там «Найти меня» подставляет координаты в форму
  точки («Поставить пин здесь»), и они сохраняются в `points.lat/lng` только по
  кнопке «Сохранить точку». Это адрес кофейни, а не местоположение гостя.
- Разрешение спрашивается только по нажатию кнопки: в браузере — диалог сайта,
  в приложении — диалог Android (разрешения `ACCESS_FINE_LOCATION` /
  `ACCESS_COARSE_LOCATION` в манифесте, запрос из `MapWebView.android.kt`).
- Отказ обрабатывается текстом на карте, повторного запроса без действия
  пользователя нет.
- Приложение использует геолокацию только пока открыта вкладка «Точка на карте»;
  в фоне и при закрытом WebView запросов нет.
- В политике конфиденциальности геолокация должна быть указана и как наша
  функция (по кнопке), и как автоматический сбор Яндекса по п. 8.1.

## Лимиты и риски

- **6.5.1** — Tiles API разрешён и для коммерческого, и для некоммерческого
  использования, в открытых и закрытых системах; свои данные поверх тайлов
  размещать можно. Это отличие от JavaScript API/MapKit, где коммерция только по оферте.
- **6.5.2** — не больше **30 запросов в секунду** на ключ, один тайл = один запрос.
  Яндекс вправе сам снижать лимит в зависимости от общей нагрузки.
- **6.7** — при превышении лимитов доступ блокируется **без предварительного
  уведомления**: ключ, IP и/или HTTP Referer. Разблокировка — только коммерческие
  условия или отдельный договор.
- **4.5 / 10.1** — Яндекс может ограничить число обращений и приостановить доступ
  по своему усмотрению.
- **4.2** — при суточной аудитории больше 100 000 пользователей нужно **до начала
  использования** написать на maps-api@support.yandex.ru.
- **4.1.1** — сервисы нельзя использовать в проектах, требующих оплаты или иным
  образом ограничивающих доступ третьих лиц; обычная регистрация ограничением не
  считается. Платный тариф владельца относится к нашей услуге, а не к доступу к карте.
- **5.1.6** — данные API нельзя хранить и обрабатывать, кроме временного кэша
  «для работоспособности» не дольше 30 дней.
- **5.1.5** — второй аккаунт в Кабинете разработчика ради обхода лимитов запрещён.
- **8.1** — Яндекс автоматически собирает IP, ID устройства и геолокацию посетителей
  сайта/приложения, а мы обязаны иметь их согласия на сбор, передачу и хранение.
  Отсюда: пункт про Яндекс Карты в политике конфиденциальности (152-ФЗ).

## Если понадобится больше 30 rps

1. Серверный кэш тайлов: прокси с кэшем отдаёт повторяющиеся тайлы сам, к Яндексу
   уходит кратно меньше запросов (ключом подписывает backend, секрет — в OpenBao).
2. Письмо на paid-api-maps@yandex-team.ru: ФИО/название организации, цель, причины,
   какие нужны rps. По п. 4.2.5 оферты возможен тестовый период до 14 дней.
3. Коммерческая лицензия: минимальный платёж предоплатой, срок 1 год с автопродлением,
   НДС не облагается (пп. 26 п. 2 ст. 149 НК РФ). Итоговая сумма фиксируется
   односторонним актом, возражения — 13 календарных дней с конца отчётного периода.

## Ключи

- Значение ключа **публичное**: попадает в JS-бандл лендинга (`VITE_YANDEX_TILES_KEY`,
  GitHub variable → docker build-arg). Защита — ограничения ключа в кабинете.
- Секрет подписи **приватный**: в код, `.env.local`, CI и APK не попадает. Для
  клиентской карты в кабинете Яндекса включён режим «Опциональная» (подпись не
  обязательна). Строгая подпись возможна только через backend-прокси.
